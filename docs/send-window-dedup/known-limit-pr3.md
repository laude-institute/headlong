Scope: PR 3 on audel/send-window-dedup.

Known limit on collision handling: one pending due time per name. The scheduler keeps a single pending due time for each thinker name. When a crashed occurrence leaves a stale claim and a wake is already scheduled for the same name, the sweep drops the claim and keeps the scheduled time. Before this change it force-wrote the past due time of the claim over the schedule, which fired the wake immediately and off window. The dropped occurrence is not recovered, because a wake file carries only the name-keyed payload with no per-occurrence content, so there is nothing from the crashed occurrence to re-fire. In practice a one-shot job that crashes and is then rescheduled under the same name inside the stale window runs only at the new scheduled time, and the missed time is never honored. A stale claim with no scheduled wake for its name is still re-fired, so plain crash recovery is unchanged. If two occurrences must both survive a crash, give them different names.
